# 记者选拔回避与复核

本仓库实现记者选拔的盲评封卷流程：报名脱敏、评委回避、评分锁定、申诉裁决与封卷审计，供业务团队在统一语义上继续建设。

## 已有内容

- `contracts/domain.schema.json`：领域事件的基础字段、聚合类型和事件名称。
- `data/sample.json`、`data/sample-flow.json`：可用于联调的中文样例记录。
- `src/vocabulary.js`：事件类型与聚合类型的唯一权威来源（与契约 schema 由测试保证一致）。
- `src/eventStore.js`：追加式事件库，按聚合做乐观并发校验。
- `src/service.js`：盲评封卷领域服务（事件溯源，内存状态可由事件库重放重建）。
- `src/validator.js`：基础事件信封与词汇校验。
- `tests/`：覆盖迟报关系、替补重评、并发封卷、跨阶段申诉等场景。

## 流程总览

1. **报名与脱敏**：`acceptEntry` 受理报名并按资格版本生成脱敏评审包（身份、联系方式字段不进入评审包，剔除字段留痕）；`reviseEntry` 在资格版本变化时生成新评审包，旧版本保留。
2. **回避事实**：`declareRecusal` 申报评委的任职、合作、指导关系，带生效区间。分配前 `proposeAssignment` 自动筛查冲突并挂起；迟报会回溯既有分配，但只标记评分时间落在生效区间内的分配。冲突一律由独立合规人员 `confirmConflict` 确认或驳回（名单外人员与当事评委均不能确认）。
3. **隔离与替补**：确认冲突只隔离受影响评分（`SCORE_QUARANTINED`，保留审计不删除）；`replaceAssignment` 派替补评委，替补同样经过冲突筛查，且通过 `judgeWorkspace` 只能看到脱敏评审包与本人评分，看不到旧分。
4. **评分锁定**：`submitScore` 提交即锁定量表版本与证据。完全相同的重传沿用原结果（幂等）；同编号异内容转入调查，原结果继续有效，`resolveInvestigation` 维持原表或把更正作为后继版本追加。
5. **阶段决定**：`publishStageList` 公布后名单不可重写；`appendDecision` 只能追加暂缓、复核或更正决定，最终状态由全部记录依次解释。
6. **申诉**：`openAppeal` 可针对任何已公布阶段（含更早阶段，即跨阶段申诉）；材料分批到达（同批同内容幂等，同批异内容拒绝）；裁决须法务与业务分别签署且意见一致，复核/更正裁决联动追加阶段决定。
7. **封卷与恢复**：`sealCase` 在无待确认冲突、未裁决申诉、未解决调查时封卷；并发封卷由事件库版本校验保证只有一笔成功。系统中断后在同一事件库上重建服务，`resume` 补发积压通知并列出未封卷案件继续办理。
8. **解释查询**：`explainCandidate` 还原一名候选人在每个阶段使用了哪些有效评分、哪些被排除及原因、追加决定如何改变最终状态，以及申诉与封卷结果。

## 领域边界

事件一旦被接收，其标识、发生时间和版本不应被原地改写；业务更正应产生后继记录。涉及个人、机构或商业敏感信息时，调用方只读取完成职责所必需的字段（评委工作台即按此约束暴露数据）。已封卷案件拒绝任何变更；封卷后新申报的回避只留审计记录，不再改动已封卷评分。

```bash
node --test
```

## 测试与构建

测试命令：

```bash
npm test
```

编译或构建命令：

```bash
npm run build
```

上述命令均在单个 Linux 应用容器内执行，不需要另行启动外部服务。
